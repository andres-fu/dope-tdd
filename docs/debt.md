# Debt ledger

Known shortcuts and deferred work, one line each, so nothing is lost and
nothing slows the current pass down. Add when you take a shortcut; strike
when you pay it. Source tags: `arch` = the 2026-10-08 architect review,
`review` = the same night's code review, `owner` = the owner's asks,
`live` = a live playground run, `arch2` = the second architect review (2026-10-08),
`docs` = the official plugin and mods docs at code.claude.com,
`checkmate` = ideas from github.com/rcrsr/checkmate, a lint-on-edit Claude Code plugin (2026-10-13).

## Correctness

- [ ] `arch 6` Full file texts live in session state and in the catch journal; the store caps at 4 MiB. Move to content hashes plus blobs (`git hash-object -w` or a plugin temp file). Audit 2026-10-18: the journal in `$.store` is the only copy that is surely written to disk; `$.state` may be memory only (the host does not say). Partly paid: journals carry a time and are settled only in their own project, session logs are pruned after 30 days, kept changes are never pruned but named at each start, source text never reaches the log. Open: hashes in place of texts, which touches the revert and restore path.
- [~] `arch 6b` Paid in part 2026-10-16 (#27): in the throwaway worktree (a Node runner, a git clone), a new file gets up to four mutants (flipped comparison or `&&`/`||`, nudged integer, negated `if`, swapped boolean; never strings or comments; no `<`/`>` in TypeScript), each run once. A red for any is PROVEN, with the rest named; none is MISSED, with each named. Before, every new file was `unverified: new file`, and the agent proved it by hand (#21). Open: experimental runners and checks in place still say `unverified: new file`; mutants are chosen by position, not by what the test exercises. A new source file is `unverified: new file`. A real check (rename away, run, restore) is possible but is the riskiest write the plugin could make on Windows under an editor or watcher.
- [ ] `arch 4` PASS lines are not read: a whole-suite run where the module's own test passed and another file failed is "red elsewhere", not green for the module.
