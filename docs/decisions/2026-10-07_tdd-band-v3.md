# 2026-10-07 — TDD band v3: close the Bash bypass, checkable state, honest RED

## What was decided
1. **Bash bypass closed.** The guard only watched Edit/Write, so a source edit
   made through a shell command (`sed -i`, redirects, a Python/Node script) went
   unseen. Now:
   - Before a Bash call, a command that names a `src/**/*.ts(x)` file together
     with a write marker (`sed -i`, `>`/`>>`, `tee`, `cp`/`mv` into src,
     `open(..., 'w')`, `writeFileSync`, `.write(`) is denied unless that
     module's test was touched (same rule as Edit/Write; pause lifts it).
   - After a Bash call, `git diff --numstat` + untracked files under `src/` are
     compared with the snapshot taken before it. Source files the call changed
     count as test-first when unlocked, otherwise as **unguarded**, and the
     model gets a reminder in the tool result.
2. **State is checkable.** `/tdd` prints the status and the recent event log;
   the model can call `mcp__tdd-guard__status` for the same. Pause/Resume and
   Reset toast a confirmation.
3. **RED means a failing test.** Phases: idle → WRITING (a test was touched,
   not yet run) → RED (last run failed) → GREEN (last run passed). A cycle
   starts at the first test touch or failing run after GREEN/idle and
   completes on the next passing run. A cycle that reaches GREEN without ever
   failing is counted as **never saw red** (the test may not test anything).
   An event log (last 50: touch, edit, run, block, pause) makes timing
   traceable.
4. **Current module follows the work.** Set by a test touch, an allowed source
   edit, or a test run naming a test file; cleared after GREEN plus 15 minutes
   without TDD events.

## Why
The owner noticed the band could not be trusted: the guard was paused with no
way to confirm, the model bypassed it via Bash during the Hueso restyle, and
"AVG 6S" cycles did not match reality because RED started at a test edit.

## Alternatives considered
- Denying every Bash call that touches `src/` — too blunt; reads and test
  runs mention src paths constantly.
- Only the post-hoc git diff check (no pre-call deny) — catches everything but
  never prevents; kept as the backstop, with the deny for obvious writes.
- A file watcher — no long-lived watcher primitive suited to this; git diff
  around each call is simpler and exact enough.

## Trade-offs accepted
- Write detection before a call is a heuristic; the git diff after the call
  is the source of truth, so a missed pattern still gets counted as unguarded.
- Two `git` invocations per Bash call (cheap, but not free).
- Files changed outside Claude's Bash calls (the person's editor) are not
  attributed; that matches the guard's purpose (keeping Claude honest).
