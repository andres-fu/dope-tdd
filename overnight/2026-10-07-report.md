## Catch check design summary (red-first)

Keep the before/after text of each source file edited in the cycle (the
Edit/Write hook already sees them); at GREEN write `before`, run only the
mirrored test with `$.process.run` under a budget, write `after` in a
`finally`, read back to verify, journal in `$.store` so a crash is repaired
on the next `session.start`. No git command touches the tree, so a dirty
tree elsewhere does not matter. Outcomes: caught, caught (new module), not
caught (advisory), inconclusive with a reason (load error, timeout, runner,
changed outside), unchecked for shell-made edits. Synchronous inside the
Bash hook for the MVP, with a `checking` flag that denies parallel edits.
Ten failing tests listed in order. Stryker incremental is the recommendation
for breadth in CI, not in the loop.
